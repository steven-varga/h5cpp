## 1. Problem Statement

The current scatter/gather implementation (landed in 2026-Q2 on branch `34-musl-static-linux`) emits I/O-heavy specializations:

```cpp
template<> inline h5::ds_t scatter<T>(hid_t fd, const std::string& path, const T& obj);
template<> inline void   gather<T>(hid_t fd, const std::string& path, T& obj);
```

These specializations **mix type conversion with HDF5 API calls** — they open datasets, create dataspaces, handle chunking, and write rows. This is the wrong separation of concerns:

- The compiler's job is **type conversion** (C++ layout ↔ on-disk layout).
- The library's job is **I/O** (open, create, read, write).
- Call-site properties (`h5::chunk`, `h5::gzip`, `h5::dapl`) are silently dropped for scatter types because the generated code hardcodes everything.

This document specifies the **visitor refactor**: pure conversion functions generated by the compiler, uniform I/O dispatch in the library.

---

## 2. Design Goal

Separate concerns:

| Layer | Responsibility | Emits/Owns |
|---|---|---|
| **Compiler** | Type conversion only | `row_t`, `scatter<T>(T*, n)`, `gather<T>(row_t*, n, space)` |
| **Library** | I/O only (open, create, read, write) | `h5::write`, `h5::read`, dataset lifecycle |

User-facing API is unchanged:

```cpp
h5::write(fd, "sensor/timeseries", ts);        // works for POD and non-POD
h5::read(fd, "sensor/timeseries", ts_back);    // works for POD and non-POD
```

The dispatch is compile-time via `h5::has_scatter<T>`.

## 3. Generated Code Specification

For each tier-2+ type `T`, the compiler emits **three artifacts** in the generated header.

### 3.1 `row_t` — on-disk layout mirror

```cpp
namespace h5::generated::TYPE_NAME_ {
    struct row_t {
        // scalar fields inline
        // indirect fields as hvl_t (std::vector) or char* (std::string)
    };

    inline hid_t compound_type() {
        // lazy-init H5T_COMPOUND with H5Tvlen_create / H5T_VARIABLE
    }
}
```

Rules:
- `row_t` is a **POD struct** — no constructors, no methods, standard layout.
- `[[h5::ignore]]` fields are omitted entirely.
- `[[h5::name("label")]]` affects `H5Tinsert` field names, not `row_t` member names.

### 3.2 `scatter<T>` — C++ → row conversion

```cpp
namespace h5 {
    template<> inline std::pair<row_t*, std::size_t>
    scatter<T>(const T* src, std::size_t n) {
        using namespace ::h5::generated::TYPE_NAME_;
        auto* rows = new row_t[n]();        // zero-initialise
        for (std::size_t i = 0; i < n; ++i) {
            rows[i].scalar_field = src[i].scalar_field;
            rows[i].string_field = const_cast<char*>(src[i].string_field.c_str());
            rows[i].vector_field = hvl_t{src[i].vector_field.size(), src[i].vector_field.data()};
        }
        return {rows, n};
    }
}
```

Rules:
- **Shallow views only.** `char*` points into `std::string::c_str()`; `hvl_t.p` points into `vector.data()`.
- **Zero-copy.** No allocation per element; only the `row_t` array itself is allocated.
- **Zero-initialized.** `new row_t[n]()` ensures `[[h5::ignore]]` fields and padding are zero.
- **Caller owns the returned `row_t*` and must `delete[]` it after `H5Dwrite`.**

### 3.3 `gather<T>` — row → C++ conversion + reclamation

```cpp
namespace h5 {
    template<> inline std::pair<T*, std::size_t>
    gather<T>(row_t* rows, std::size_t n, hid_t reclaim_space) {
        using namespace ::h5::generated::TYPE_NAME_;
        auto* dst = new T[n];
        for (std::size_t i = 0; i < n; ++i) {
            dst[i].scalar_field = rows[i].scalar_field;
            if (rows[i].string_field) dst[i].string_field.assign(rows[i].string_field);
            dst[i].vector_field.assign((double*)rows[i].vector_field.p,
                                       (double*)rows[i].vector_field.p + rows[i].vector_field.len);
        }
#if H5_VERSION_GE(1,12,0)
        H5Treclaim(compound_type(), reclaim_space, H5P_DEFAULT, rows);
#else
        H5Dvlen_reclaim(compound_type(), reclaim_space, H5P_DEFAULT, rows);
#endif
        delete[] rows;
        return {dst, n};
    }
}
```

Rules:
- **Deep copy.** All VLEN data is copied into `std::string` / `std::vector`.
- **Reclaims HDF5-allocated VLEN memory** via version-gated `H5Treclaim` (1.12+) or `H5Dvlen_reclaim` (1.10).
- **Frees the `row_t` array** after reclamation.
- **Caller owns the returned `T*` and must `delete[]` it.**

## 4. Library Changes

### 4.1 `h5cpp/H5Tall.hpp`

Add `scatter_traits<T>` declaration:

```cpp
namespace h5 {
    template <typename T> struct has_scatter : std::false_type {};

    /**
     * @brief Maps a scatter-eligible C++ type to its generated row type.
     *
     * The h5cpp-compiler emits specializations for each tier-2+ struct:
     *   template<> struct scatter_traits<sn::sensor::timeseries_t> {
     *       using row_type = h5::generated::sn__sensor__timeseries_t_::row_t;
     *   };
     */
    template <typename T> struct scatter_traits;
} // namespace h5
```

### 4.2 `h5cpp/H5Dwrite.hpp`

Replace the current scatter dispatch. The library creates/opens the dataset using `scatter_traits<T>::compound_type()` and writes the row array directly:

```cpp
// BEFORE (current):
if constexpr (h5::has_scatter<std::decay_t<T>>::value) {
    return h5::scatter<std::decay_t<T>>(fd, dataset_path, ref);  // args dropped
}

// AFTER (visitor):
if constexpr (h5::has_scatter<std::decay_t<T>>::value) {
    using traits = h5::scatter_traits<std::decay_t<T>>;
    auto [rows, n] = h5::scatter<std::decay_t<T>>(
        h5::impl::data(ref), h5::impl::element_count(ref));

    // --- dataset creation (same policy as POD path, custom compound type) ---
    h5::ds_t ds;
    h5::mute();
    bool exists = H5Lexists(fd, dataset_path.c_str(), H5P_DEFAULT) > 0;
    h5::unmute();
    if (exists) {
        const h5::dapl_t& dapl = arg::get(h5::default_dapl, args...);
        ds = h5::open(fd, dataset_path, dapl);
    } else {
        using tcurrent_dims = typename arg::tpos<const h5::current_dims_t&, const args_t&...>;
        h5::count_t count{n};
        h5::current_dims_t current_dims = h5::impl::get_current_dims(count, args...);
        ds = h5::createds(fd, dataset_path, traits::compound_type(),
            h5::sp_t{H5Screate_simple(1, &current_dims.count, ...)}, ...);
    }

    // --- write rows ---
    H5Dwrite(ds, traits::compound_type(), H5S_ALL, H5S_ALL, H5P_DEFAULT, rows);
    delete[] rows;   // shallow views — HDF5 already copied in H5Dwrite
    return ds;
}
```

Notes:
- `args...` (chunk, compress, dapl, etc.) are extracted and used for dataset creation, just like the POD path.
- `h5::compat::span<T>` is **not needed here** because the write is a single `H5Dwrite` call on the raw `rows` pointer.

### 4.3 `h5cpp/H5Dread.hpp`

Replace the current gather dispatch:

```cpp
// BEFORE (current):
if constexpr (h5::has_scatter<std::decay_t<T>>::value) {
    h5::gather<std::decay_t<T>>(fd, dataset_path, ref);
}

// AFTER (visitor):
if constexpr (h5::has_scatter<std::decay_t<T>>::value) {
    using traits = h5::scatter_traits<std::decay_t<T>>;

    // Read raw rows through normal HDF5 read (dataset → memory)
    h5::ds_t ds = h5::open(fd, dataset_path, arg::get(h5::default_dapl, args...));
    h5::sp_t file_space = H5Dget_space(ds);
    hsize_t n = H5Sget_simple_extent_npoints(file_space);
    auto* rows = new traits::row_type[n];
    H5Dread(ds, traits::compound_type(), H5S_ALL, H5S_ALL, H5P_DEFAULT, rows);

    // Convert + reclaim
    auto [dst, m] = h5::gather<std::decay_t<T>>(rows, n, file_space);
    H5Sclose(file_space);

    // Move result into user ref
    h5::impl::move_into(ref, dst, m);
    delete[] dst;
}
```

### 4.4 `H5CPP_REGISTER_SCATTER` macro

Retained but simplified. It now only sets `has_scatter<T>` and `scatter_traits<T>`:

```cpp
#define H5CPP_REGISTER_SCATTER(SCATTER_TYPE)                            \
    namespace h5 {                                                      \
        template<> struct has_scatter<SCATTER_TYPE> : std::true_type {}; \
        template<> struct scatter_traits<SCATTER_TYPE> {                \
            using row_type = ::h5::generated::SCATTER_TYPE##_::row_t;   \
        };                                                              \
    }
```

(The actual macro uses the mangled namespace name, not a string-paste.)

## 5. Memory Management Rules

| Phase | Who allocates | Who frees | How |
|---|---|---|---|
| `scatter` | Compiler-generated code | Caller (`h5::write`) | `new row_t[n]()` → `delete[]` |
| `H5Dwrite` | HDF5 (internally, for vlen global heap) | N/A (managed by file) | Implicit |
| `H5Dread` | Library (`h5::read`) | `gather` (via `H5Dvlen_reclaim`) | Reclaim + `delete[] rows` |
| `gather` | Compiler-generated code | Caller (`h5::read`) | `new T[n]` → `delete[]` |

**Key invariant:** `scatter` produces shallow views valid only for the duration of the `H5Dwrite` call. `gather` consumes HDF5-allocated rows, reclaims them, and produces deep-copied C++ objects.

## 6. Recursive Applicability

**Yes — for nested user-defined types.**

If a tier-2 struct `Outer` contains another tier-2 struct `Inner` as a field, the compiler generates a nested `row_t`:

```cpp
namespace h5::generated {
    struct Inner_row_t { hvl_t values; };
    struct Outer_row_t { int id; Inner_row_t inner; char* label; };
}
```

`scatter<Outer>` simply populates the nested `Inner_row_t` inline — no recursive function call needed because the layout is flat-at-the-row-level. HDF5 compound types compose recursively, and `H5Dvlen_reclaim` / `H5Treclaim` recursively reclaim nested vlen memory.

**No — for container nesting or self-referential types.**
- `std::vector<std::vector<T>>` (ragged arrays) are tier-3 and handled by existing h5cpp container templates before scatter is considered.
- `std::vector<T>` where `T` is scatter-eligible is fully supported: the container template extracts `T*` and count, scatter converts the flat array.
- Self-referential structs (`struct Node { std::vector<Node> children; }`) are tier-4 (opaque / tree-walk) and out of scope.

## 7. Migration Plan

### Phase 1 — Library prep (this PR)

1. Add `scatter_traits<T>` to `H5Tall.hpp`.
2. Refactor `H5Dwrite.hpp` dispatch to use visitor `scatter` + explicit dataset creation with `compound_type()`.
3. Refactor `H5Dread.hpp` dispatch to use `H5Dread` into row buffer + visitor `gather`.
4. Verify all existing examples still build.

### Phase 2 — Compiler refactor (follow-up PR)

1. `producer_h5.hpp`: replace `scatter_type()` I/O emission with pure visitor emission.
2. Emit `scatter_traits<T>` specialization alongside `has_scatter<T>`.
3. Remove old `scatter(fd, path, obj)` and `gather(fd, path, obj)` signatures.
4. Update example `generated.h` files.

### Phase 3 — Example update

1. Update `examples/compound/` to use the new `h5::write`/`h5::read` calls (remove explicit `scatter`/`h5::gather`).
2. Add a test that verifies call-site args work for scatter types:
   ```cpp
   h5::write(fd, "ts", ts, h5::chunk{256} | h5::gzip{9});
   ```

## 8. Testing Requirements

| Test | What it proves |
|---|---|
| `examples-compound` builds and runs | End-to-end visitor path works |
| `h5::write(fd, path, ts, h5::chunk{N})` compiles and creates correct chunk size | Call-site args forward through visitor |
| Read-back data equals written data | `gather` deep-copies correctly |
| `[[h5::ignore]]` field not present in file | `row_t` omits ignored fields |
| `[[h5::name("label")]]` field has correct HDF5 name | `compound_type()` uses renamed fields |
| `std::string` with Unicode round-trips | VLEN string path works |
| `std::vector<double>` with 0, 1, N elements round-trips | Edge cases in VLEN size |
| Nested tier-2 struct round-trips | Recursive applicability |

## 9. Reference: Complete Generated Header (Target)

```cpp
#pragma once
#include <h5cpp/all>
#include "non-pod.h"

namespace h5::generated::sn__sensor__timeseries_t_ {

struct row_t {
    unsigned long long timestamp_ns;
    char*    tag;
    hvl_t    readings;
};

inline hid_t compound_type() {
    static const hid_t ct = []{
        hid_t v_tag = H5Tcopy(H5T_C_S1);
        H5Tset_size(v_tag, H5T_VARIABLE);
        hid_t v_readings = H5Tvlen_create(H5T_NATIVE_DOUBLE);
        hid_t ct = H5Tcreate(H5T_COMPOUND, sizeof(row_t));
        H5Tinsert(ct, "timestamp_ns", HOFFSET(row_t, timestamp_ns), H5T_NATIVE_ULLONG);
        H5Tinsert(ct, "label",        HOFFSET(row_t, tag),      v_tag);
        H5Tinsert(ct, "readings",     HOFFSET(row_t, readings), v_readings);
        return ct;
    }();
    return ct;
}

} // namespace h5::generated::sn__sensor__timeseries_t_

// --- visitor: pure conversion, no HDF5 calls ---

namespace h5 {
    template<> inline std::pair<row_t*, std::size_t>
    scatter<sn::sensor::timeseries_t>(const sn::sensor::timeseries_t* src, std::size_t n) {
        using namespace ::h5::generated::sn__sensor__timeseries_t_;
        auto* rows = new row_t[n]();
        for (std::size_t i = 0; i < n; ++i) {
            rows[i].timestamp_ns = src[i].timestamp_ns;
            rows[i].tag          = const_cast<char*>(src[i].tag.c_str());
            rows[i].readings     = hvl_t{src[i].readings.size(), src[i].readings.data()};
        }
        return {rows, n};
    }

    template<> inline std::pair<sn::sensor::timeseries_t*, std::size_t>
    gather<sn::sensor::timeseries_t>(row_t* rows, std::size_t n, hid_t reclaim_space) {
        using namespace ::h5::generated::sn__sensor__timeseries_t_;
        auto* dst = new sn::sensor::timeseries_t[n];
        for (std::size_t i = 0; i < n; ++i) {
            dst[i].timestamp_ns = rows[i].timestamp_ns;
            if (rows[i].tag) dst[i].tag.assign(rows[i].tag);
            dst[i].readings.assign((double*)rows[i].readings.p,
                                   (double*)rows[i].readings.p + rows[i].readings.len);
        }
#if H5_VERSION_GE(1,12,0)
        H5Treclaim(compound_type(), reclaim_space, H5P_DEFAULT, rows);
#else
        H5Dvlen_reclaim(compound_type(), reclaim_space, H5P_DEFAULT, rows);
#endif
        delete[] rows;
        return {dst, n};
    }
}

// --- trait registration ---

H5CPP_REGISTER_SCATTER(sn::sensor::timeseries_t);
```
